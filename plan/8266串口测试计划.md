# 8266 串口模拟测试计划

用 PC + USB-TTL 冒充 ESP8266，经 UART1（P3.0/P3.1）驱动 51 固件全部协议逻辑，免真实 ESP 即可验证固件行为。配合 `tools/uart_8266_sim.py`。

## 1. 硬件连接（关键）

- **断开/移除板载 ESP-01S**：板载 51 与 ESP 共用同一对 UART 线，若 ESP 在线会与 USB-TTL 总线冲突。测试时只留 51 + USB-TTL 两根线直连。
- 接线（交叉）：
  - 适配器 `TXD` → 51 `P3.0`（RXD）
  - 适配器 `RXD` → 51 `P3.1`（TXD）
  - 适配器 `GND` → 51 `GND`
- 电平：51 为 **5V TTL**。
  - 适配器 `TXD` 输出 3.3V 即可被 51 读为高（VIH≈2V），绝大多数 CH340/CP2102 满足。
  - 适配器 `RXD` 须 **5V 容忍**（多数 CH340/CP2102 是）；若非 5V 容忍，在「51-TX → 适配器-RX」串 1k+1k 分压或加电平转换，否则烧适配器。
- 波特率 **9600 / 8 / N / 1**。

## 2. 帧格式（权威来源：firmware/STC/src/main.c、plan/串口通信协议.md）

```
[0xAA][0x55][CMD][LEN][PAYLOAD...][CHK]
CHK = XOR(CMD, LEN, PAYLOAD[0..LEN-1])
```

- 解析状态机：`AA`→`55`→`CMD`→`LEN`→`PAYLOAD[0..LEN-1]`→`CHK`。`AA` 后非 `55` 直接复位；`LEN>60` 丢弃（防 p_buf[64] 越界）。
- **门控**：`SET_TIME/SET_CFG/NET_STAT/STA_IP/REQ_CFG` 仅在 51 收到 `BOOT(0x8F)` 后置 `esp_online=1` 才生效。故任何下行测试前先发 `BOOT`。
- 51 主动上发：`HEARTBEAT(0x02)`（正常模式每 ~1s）、`REQ_TIME(0x01)`、`REQ_CFG(0x87)`→回 `SET_CFG(0x82,54B)`、`ENTER_AP(0x04)`（双键长按）。

## 3. 命令码（与固件 #define 一致）

| 方向 | CMD | 值 | 载荷 |
|---|---|---|---|
| MCU→ESP | REQ_TIME | 0x01 | — |
| MCU→ESP | HEARTBEAT | 0x02 | — |
| MCU→ESP | ENTER_AP | 0x04 | — |
| ESP→MCU | BOOT | 0x8F | — |
| ESP→MCU | SET_TIME | 0x81 | 8B：YY MM DD WD HH MM SS TZ（BCD） |
| ESP→MCU | SET_CFG | 0x82 | 54B（&cfg 镜像） |
| ESP→MCU | NET_STAT | 0x83 | 1B 状态 |
| ESP→MCU | REQ_CFG | 0x87 | — |
| ESP→MCU | STA_IP | 0x88 | 4B IP |

## 4. 工具用法

```bash
pip install pyserial
python tools/uart_8266_sim.py monitor COM3            # 仅监听 51 发出的帧
python tools/uart_8266_sim.py server  COM3            # 冒充 ESP：发 BOOT + 自动应答
python tools/uart_8266_sim.py boot    COM3            # 发 BOOT 握手
python tools/uart_8266_sim.py send    COM3 83 02      # 发 NET_STAT=联网
python tools/uart_8266_sim.py settime COM3 12:34:56 --tz 8
python tools/uart_8266_sim.py setcfg  COM3 cfg.bin   # 发 54B 配置（无文件则全 0）
python tools/uart_8266_sim.py staip   COM3 192.168.1.10
```
（Windows 端口名形如 `COM3`；Linux 为 `/dev/ttyUSB0`）

## 5. 两种测试模式

- **正常模式（推荐，安静）**：先启动 `server`，再给 51 上电/复位，使 `BOOT` 在 2s 内到达 → 51 不打印、专收协议帧。验证靠「效果」（时间被改写、配置回读一致等）。
- **调试模式（可见）**：不连适配器直接给 51 上电 → 3 声蜂鸣、51 进入调试模式（极详细日志 + 仍解析串口帧）。脚本帧解析器对非帧字节（ASCII 日志）自动忽略。适合边看日志边验证，但日志会拖慢主循环。

> 两种模式下都需先发 `BOOT` 才能让 51 接受下行帧。调试模式无需抢 2s 窗口。

## 6. 测试用例

| ID | 用例 | 操作 | 预期 |
|---|---|---|---|
| T01 | 上电检测 | 不连适配器上电 | 3 声蜂鸣（调试模式） |
| T02 | BOOT 握手 | `server` 连上即发 BOOT | 51 `esp_online=1`，后续下行帧被处理 |
| T03 | 对时 | 正常模式 `server` 收到 REQ_TIME 自动回 SET_TIME；或手动 `settime` | 51 写 DS1302。验证：断电重启进调试模式，看启动 dump 的 DS1302 时间已更新 |
| T04 | 配置下发/回读 | `setcfg COM3 cfg.bin` 发 54B → `send COM3 87` 触发 REQ_CFG | 51 回 SET_CFG(0x82) 54B，应与下发一致（脚本记录 `echo_cfg`） |
| T05 | 网络状态 | `send COM3 83 02` | 51 更新 `net_status`（影响 LED/逻辑） |
| T06 | STA IP 预置 | `staip COM3 192.168.1.10`（双击 SET 触发 IP 滚显，需物理键） | 51 缓存末段 IP，供显示；脚本只负责预置 |
| T07 | 重配网 | 物理双键 ≥5s → 51 发 ENTER_AP(0x04)；脚本可回 AP_READY(0x84) | 收到 0x04 帧即代表双键长按逻辑触发 |
| T08 | 心跳 | 正常模式空跑 `monitor` | 51 每 ~1s 发 HEARTBEAT(0x02)；`server` 自动回 NET_STAT 不丢帧 |
| T09 | 错误帧 | `send` 故意改错 CHK 字节 / 发随机乱码 | 51 丢弃（无动作、无应答） |
| T10 | 按键物理项 | 见 `plan/硬件生产测试计划.md` | 亮度/时间设置/模式切换/计时器属物理键测试，不在串口范围 |

## 7. 已知功能缺口（测试时标注，非 bug）

- 计时器（51 原生）**已实现**（长按 UP 进/出，单击 UP 起停、单击 SET 归零，封顶 99:59）；倒计时**权威在 8266**，51 仅显示 `DISP_OVERRIDE(0x89)` 推送的 MM:SS 并经 `CD_CTRL(0x05)` 转发设备键（单击 SET=暂停/恢复，长按 SET=取消）。设备端 IP 滚显已裁掉（容量取舍）。
- NTC 当前为线性近似占位（`ntc_temp_x10`，B=4050/10K 上拉/零点 raw≈512），精度靠 Web `temp_offset` 单点标定；Steinhart-Hart 待升级（见 `plan/原理图.md §9`）。
- `KEY_UP EV_LONG` 计时器、IP 显示（双击 SET）、重配网（双键长按）均需**物理按键**触发，串口脚本无法直接驱动。
