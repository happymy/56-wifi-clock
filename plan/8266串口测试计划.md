# 8266 串口模拟测试计划

用 PC + USB-TTL 冒充 ESP8266，经 UART1（P3.0/P3.1）驱动 51 固件全部协议逻辑，免真实 ESP 即可验证固件行为。配合 `firmware/STC/test/uart_8266_sim.py`。

## 1. 硬件连接（关键）

- **断开/移除板载 ESP-01S**：板载 51 与 ESP 共用同一对 UART 线，若 ESP 在线会与 USB-TTL 总线冲突。测试时只留 51 + USB-TTL 两根线直连。
- 接线（交叉）：
  - 适配器 `TXD` → 51 `P3.0`（RXD）
  - 适配器 `RXD` → 51 `P3.1`（TXD）
  - 适配器 `GND` → 51 `GND`
- 电平：51 为 **5V TTL**。
  - 适配器 `TXD` 输出 3.3V 即可被 51 读为高（VIH≈2V），绝大多数 CH340/CP2102 满足。
  - 适配器 `RXD` 须 **5V 容忍**（多数 CH340/CP2102 是）；若非 5V 容忍，在「51-TX → 适配器-RX」串 1k+1k 分压或加电平转换，否则烧适配器。
- 波特率 **9600 / 8 / N / 1**。

## 2. 帧格式（权威来源：firmware/STC/src/main.c、plan/串口通信协议.md）

```
[0xAA][0x55][CMD][LEN][PAYLOAD...][CHK]
CHK = XOR(CMD, LEN, PAYLOAD[0..LEN-1])
```

- 解析状态机：`AA`→`55`→`CMD`→`LEN`→`PAYLOAD[0..LEN-1]`→`CHK`。`AA` 后非 `55` 直接复位；`LEN>60` 丢弃（防 p_buf[64] 越界）。
- **门控**：`SET_TIME/SET_CFG/NET_STAT/STA_IP/REQ_CFG` 仅在 51 收到 `BOOT(0x8F)` 后置 `esp_online=1` 才生效。故任何下行测试前先发 `BOOT`。
- 51 主动上发：`HEARTBEAT(0x02)`（正常模式每 ~1s）、`REQ_TIME(0x01)`、`REQ_CFG(0x87)`→回 `SET_CFG(0x82,54B)`、`ENTER_AP(0x04)`（双键长按）。

## 3. 命令码（与固件 #define 一致）

| 方向 | CMD | 值 | 载荷 |
|---|---|---|---|
| MCU→ESP | REQ_TIME | 0x01 | — |
| MCU→ESP | HEARTBEAT | 0x02 | — |
| MCU→ESP | ENTER_AP | 0x04 | — |
| MCU→ESP | CD_CTRL | 0x05 | 1B：0=暂停/恢复 1=取消（设备键 P2 下发的倒计时控制） |
| ESP→MCU | BOOT | 0x8F | — |
| ESP→MCU | SET_TIME | 0x81 | 8B：YY MM DD WD HH MM SS TZ（BCD） |
| ESP→MCU | SET_CFG | 0x82 | 54B（&cfg 镜像，双向复用） |
| ESP→MCU | NET_STAT | 0x83 | 1B 状态 |
| ESP→MCU | REQ_CFG | 0x87 | — |
| ESP→MCU | STA_IP | 0x88 | 4B IP |
| ESP→MCU | DISP_OVERRIDE | 0x89 | 1–3B：mode0=释放 / mode1=[0x01,mm,ss] 倒计时接管 / mode2=归零响铃 |

> 51 当前已实现：0x01/0x02/0x04/0x05/0x81/0x82/0x83/0x87/0x88/0x89/0x8F。
> 协议设计稿（`plan/串口通信协议.md`）另有 0x03 BTN_EVENT、0x84 AP_READY、0x85 ACK、0x86 NAK —— 均为 **8266 侧设计，51 当前未实现亦不解析**（收到不处理、亦不发送），测试时无需模拟，待 8266 固件落地后补齐。

## 4. 工具用法

```bash
pip install pyserial
python firmware/STC/test/uart_8266_sim.py monitor COM3            # 仅监听 51 发出的帧
python firmware/STC/test/uart_8266_sim.py server  COM3            # 冒充 ESP：发 BOOT + 自动应答
python firmware/STC/test/uart_8266_sim.py boot    COM3            # 发 BOOT 握手
python firmware/STC/test/uart_8266_sim.py send    COM3 83 02      # 发 NET_STAT=联网
python firmware/STC/test/uart_8266_sim.py settime COM3 12:34:56 --tz 8
python firmware/STC/test/uart_8266_sim.py setcfg  COM3 cfg.bin   # 发 54B 配置（文件字节为底，完整覆盖）
python firmware/STC/test/uart_8266_sim.py setcfg  COM3 --smg1 1 --temp-unit 1   # 仅改字段：自动先 REQ_CFG 读回 51 当前配置，只覆盖指定字节（不移除、保留亮度等按键值）
python firmware/STC/test/uart_8266_sim.py staip   COM3 192.168.1.10
python firmware/STC/test/uart_8266_sim.py cd      COM3 on 01 2D   # DISP_OVERRIDE 倒计时接管 MM:SS（⚠️ mm/ss 按十六进制解析：2D=45→显示 03:45；传 45 会被当 0x45=69 显示成 03:69）
python firmware/STC/test/uart_8266_sim.py cd      COM3 off        # 释放显示（mode0；需显式发此帧，CD_CTRL 取消不清本地显示）
python firmware/STC/test/uart_8266_sim.py cd      COM3 beep       # 归零响铃（mode2：持续响铃约 2 分钟且不接管显示，数码管保持走时）
python firmware/STC/test/uart_8266_sim.py cdctrl  COM3 0          # CD_CTRL 暂停/恢复
python firmware/STC/test/uart_8266_sim.py cdctrl  COM3 1          # CD_CTRL 取消
python firmware/STC/test/com_cfg.py   COM3                        # 回读 54B 配置并解码（闹钟时/分按 BCD 显，已修正）
```

> ⚠️ **闹钟下发用 BCD（经实测踩坑）**：`SET_CFG` 中 alarm 的时/分是 **BCD** 存储（与 DS1302 同格式，51 直读直比）。构造 54B 时须 `时=0x15`（15点）而非 `0x0F`——下发十进制二进制 `0x0F` 与 51 读回 BCD `t.hr=0x15` 永不相等，**闹钟静默不触发**（连试两次皆不响，改 BCD 后 15:05 正常响）。`com_cfg.py` 已按 BCD 解码显示。
（Windows 端口名形如 `COM3`；Linux 为 `/dev/ttyUSB0`）

> ⚠️ **SET_CFG 是完整 54B 快照，8266 编写铁律（经实测踩坑）**：51 收到 `SET_CFG(0x82,54B)` 会**整体覆盖**内存 `cfg` 并入 EEPROM，不做字节级合并。故 8266 侧**必须始终维护一份完整的 54B 配置镜像**（上线 `REQ_CFG` 拉取 51 当前值作基底），改某字段时**只改镜像中对应字节再把整份 54B 下发**；**严禁**只下发它想改的个别字节（其余填 0）——否则会清空 `bright_mode/bright_lvl`（亮度）等 51 侧按键值。`firmware/STC/test/uart_8266_sim.py setcfg --字段` 已按此实现（先 `REQ_CFG` 读回保留其它字节），可作为 8266 固件的参考实现。

## 5. 两种测试模式

- **正常模式（推荐，安静）**：先启动 `server`，再给 51 上电/复位，使 `BOOT` 在 2s 内到达 → 51 不打印、专收协议帧。验证靠「效果」（时间被改写、配置回读一致等）。
- **调试模式（可见）**：不连适配器直接给 51 上电 → 3 声蜂鸣、51 进入调试模式（极详细日志 + 仍解析串口帧）。脚本帧解析器对非帧字节（ASCII 日志）自动忽略。适合边看日志边验证，但日志会拖慢主循环。

> 两种模式下都需先发 `BOOT` 才能让 51 接受下行帧。调试模式无需抢 2s 窗口。

## 7. 已知功能缺口（测试时标注，非 bug）

- 计时器（51 原生）**已实现**（长按 UP 进/出，单击 UP 起停、单击 SET 归零，封顶 99:59）；倒计时**权威在 8266**，51 仅显示 `DISP_OVERRIDE(0x89)` 推送的 MM:SS 并经 `CD_CTRL(0x05)` 转发设备键（单击 SET=暂停/恢复，长按 SET=取消）。设备端 IP 显示已简化为 `P`+末段（双击 SET 显 ~3s），不再滚显完整 IP（容量取舍）。
- NTC 当前为线性近似占位（`ntc_temp_x10`，B=4050/10K 上拉/零点 raw≈512），精度靠 Web `temp_offset` 单点标定；Steinhart-Hart 待升级（见 `plan/原理图.md §9`）。
- `KEY_UP EV_LONG` 计时器、IP 显示（双击 SET）、重配网（双键长按）均需**物理按键**触发，串口脚本无法直接驱动。

## 8. EEPROM 读取约束（重要）

读 51 的片内 EEPROM **只有一条可行路径**，另两条设想已淘汰：

- ✅ **方法 1（可用）**：`REQ_CFG(0x87)` → 51 回 `SET_CFG(0x82, 54B)`（`config.c` 的 `cfg` 结构）。`com_cfg.py` 自动发 `BOOT(0x8F)`+`REQ_CFG` 并解码，见 T13。
  - ⚠️ 回的是**内存 `cfg`**：仅当 EEPROM 首字节 `MAGIC(0x56)` 有效（即 `cfg_load` 成功）才等于 EEPROM 内容；未初始化/被擦除时回默认值，**不是原始 flash**。
- ❌ **方法 2（淘汰）**：STC-ISP 读 Data Flash——本机烧录环境**无此功能**。
- ❌ **方法 3（淘汰）**：固件新增串口 dump 命令读任意 IAP 地址——当前 CODE 余量 **8182/8192B（余 10B）**，加不动。

故**原始整片 EEPROM（0x0000–0x13FF，含 dbg_log 环形区）读取当前不可行**；验证配置持久化只用方法 1。
