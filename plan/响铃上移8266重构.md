# 响铃判定全量上移 8266 重构方案（分支 `feat/ring-8266-migration`）

> 状态：**方案已确认（DS1302 优先时间架构拍板 2026-09-04），尚未落码**。本文件为重构的设计总纲与分阶段执行清单。
> 背景：51 端 8KB Flash 已近满（余 ~95B），整点报时此前裁撤、事项提醒从未实现。
> 目标：恢复整点报时 + 完整实现 5 组事项提醒 + 统一 3 组闹钟；所有响铃**判定在 8266**，
> 8266 全部以 **51 的 DS1302 实时时钟为准**（断电走时权威不动）→ **断网不影响任何提醒**。
> 决策（用户已定）：① 全部响铃迁 8266（闹钟+提醒+报时）；② 只在到点前高频读时钟；
> ③ 提醒配置存 8266；④ 真精简 54B→13B；⑤ 报时短滴一声、不亮屏不拦截。
> **追加需求（2026-09-04）**：⑥ 8266 可读取 51 的光敏/热敏 ADC 值（Web 温度校准自动化）；
> ⑦ 51↔8266 通信加「发送后有应答」的可靠确认层（ACK）；**⑧ 时间主从架构确认：DS1302 为唯一走时锚、NTP 仅作定期校准（见 §一 时间架构）**。
> **已定案决策（2026-09-04）**：⑨ 提醒=纯〈时,分〉不带描述文字（对齐闹钟字段，零显示层/RAM 成本）；
> ⑩ 响铃与显示**解耦**，倒计时接管显示时闹钟/提醒照响，冲突优先级=倒计时归零>闹钟/提醒长鸣>报时短滴；
> ⑪ ADC 单帧返回「光敏 raw+热敏 raw+温度×10」，8266 读 raw/温度做**展示与校准读数**，**不做回填 temp_offset**、不复刻 NTC 公式（换算权威留 51）。
> **⑫ 计时器上移 8266 + 按键事件统一上报（2026-09-04 一次性迁移）**：51 端点秒表`tm`状态机**整体删除**（计时权威/tick 移交 8266），
> 复用 `DISP_OVERRIDE` 显示接管；**实现 `BTN_EVENT(0x03)` 全按键上报，`cd_disp`（8266 接管显示）期间 51 把所有按键事件经 BTN_EVENT 发送，8266 按接管类型（倒计时/计时器/未来）统一解释，`CD_CTRL(0x05)` 废弃（功能并入 BTN_EVENT）**。
> **目标：51 彻底纯化成「显示 + 响铃 + IO 桥」小端，应用层（倒计时/计时器/响铃判定/按键裁决）全在 8266，以后新增显示接管类功能不改 51 代码。**

## 一、架构切分（最小 diff，动响应/动脉状态机尽量留 51）

| 职责 | 归属 | 说明 |
|---|---|---|
| 走时 / 时间权威 | 51 + DS1302（有电池） | **只读不改**，唯一可靠基准 |
| 时间上报给 8266 | 51 | 新增应答命令 |
| 响铃**判定**（何时响） | 8266 | 读 51 时钟 → 比对 → 下发触发帧 |
| 响铃**执行**（蜂鸣/贪睡/取消/亮屏/超时停） | 51 | **复用现有** `ring_alarm / ring_ticks / snooze_ticks / snooze_idx` 机制，本地自治 |
| 闹钟 3 组 + 提醒 5 组 + 报时开关 | 8266 | 本地 EEPROM 存储，Web 直接改并即时生效，不占 51 配置 |
| 倒计时 + 计时器（双应用）+ 按键语义裁决 | 8266 | 1s 推帧/状态机/显示接管互斥全在 8266；`cd_disp` 期间 51 经 `BTN_EVENT` 全按键上报，8266 按接管类型裁决（决策⑫） |
| 按键**实时扫描** | 51 | 物理唯一连 51；`cd_disp` 期间转发 `BTN_EVENT`，其余走本地状态机 |

**核心思想**：51 只负责「到点收到触发 → 本地响铃 + 贪睡 + 取消 + 亮屏」，8266 只负责「判断到没到点 → 发一次触发」。响铃的边角状态（重响、贪睡、取消确认音）全部由 51 现有 FSM 承接，8266 判定窗口随触发而关闭，不做跨端实时状态同步。

### 1.1 时间主从架构（已确认，铁律）

- **DS1302 = 唯一走时锚**（断电走时权威、有电池）。
- **NTP = 定期校准工具，非判定基准**：8266 联网后从 NTP 取权威时间 → `SET_TIME(0x81)` 下推校准 DS1302（清 CH、存 tz）→ 之后**判定永远读 DS1302**。
- **8266 判定瞬间必须用刚读到的 DS1302 值（P13）**，禁止混用其软件 NTP 钟——两者在下推后短期可能不一致（有推送延迟），混用会误触发。
- **断网不失效**：NTP 挂只影响对时精度，DS1302 继续走、8266 照常读照常判照常响。
- 一句话：**DS1302 是时间之锚，NTP 是定期校准它的大锤，8266 判定永远信锚不信锤。**

   - 低频（~30–60s）调 `REQ_TIME_RD` 读 51 时钟，维护「距最近触发点剩余秒数」
   - 剩余 < 5s → 切每秒精读，捕捉 `min` 翻转瞬间 → 精准触发 `send_ring`
   - 触发后恢复低频；同一时刻多触发 → **冲突消解（决策⑩）**：倒计时归零 > 闹钟/提醒长鸣 > 报时短滴；**倒计时接管显示时闹钟/提醒照响**（51 响铃与显示解耦）

4.1 **倒计时 / 计时器（新增）双显示接管应用（决策⑫）**：

## 四、新增协议命令（命令码实现时写入 `plan/串口通信协议.md`，此处列方向与语义）

### 4.1 功能命令（响铃/S时钟/ADC）

| 命令 | 方向 | 载荷 | 用途 |
|---|---|---|---|
| `REQ_TIME_RD` | ESP→51 | — | 读 DS1302 时间（区别于 `REQ_TIME 0x01` 的「请求 NTP 对时」） |
| `TIME_RD_RSP` | 51→ESP | 8B BCD | 回当前 DS1302 时间（复用 SET_TIME 载荷格式） |
| `RING` | ESP→51 | 1B mode | 0 取消 / 1 报时短滴 / 2 提醒长鸣 / 3 闹钟长鸣（倒计时归零沿用现有 `DISP_OVERRIDE mode2`） |
| `REQ_SENSOR` | ESP→51 | — | 读传感器一次（决策⑪：单帧取齐，一次请求一次应答） |
| `SENSOR_RSP` | 51→ESP | 6B | `[光敏raw hi,lo, 热敏raw hi,lo, temp×10 hi,lo]`；光敏/热敏 10 位 raw 0–1023，temp×10 有符号 ℃

- **`BTN_EVENT(0x03)`：由「不实现」改为「实现」**（决策⑫）。1B 事件码表见 `plan/串口通信协议.md §4`（0x01 单击SET/0x02 单击UP/0x03 双击SET/0x04 长按SET/0x05 长按UP/0x08 双键≥5s）。**51 在 `cd_disp`（8266 接管显示）期间把 keys.c 产出的 (btn,ev) 事件映射为 1B 事件码上报；非接管期间按键仍走 51 本地状态机（tset/bright/三态切换，不动）**。
- **`CD_CTRL(0x05)` 废弃**：倒计时按键原由 51 定向发 `CD_CTRL`（main.c:300-305）→ 改由 `BTN_EVENT` 全量上报、8266 按接管类型解释；`CD_CTRL` 协议/冻结文字在 Phase 5 一并清理，8266 端保留解析兼容（旧工装不受影响）。
- 帧格式 `AA 55 CMD LEN PAYLOAD CHK` 不变；帧间 ≥5ms 不变。

### 4.2 可靠确认层（ACK）

- **新命令 `CMD_ACK 0x85`**（协议 §既有预留 0x85 ACK / 0x86 NAK，采 0x85），载荷 **1B = 被确认帧的命令号**。
- **确认对象（只对「必须可靠送达、且无自然应答」的命令性帧 ACK，避免万能 ACK 流量爆炸 + 51 空间）**：
  - **需 ACK**：`SET_CFG`、`RING`、`DISP_OVERRIDE`（尤其 mode0 释放）——这三者**无自然应答**，丢帧有后患（配置丢失/响铃漏触发/显示卡死接管）。
  - **不需 ACK**：`HEARTBEAT`、`NET_STAT`、`BOOT`（本就周期重发兜底）、`SENSOR_RSP`、`TIME_RD_RSP`（应答/周期类，天然高频、丢帧可容忍）。
  - **`REQ_TIME_RD` / `REQ_SENSOR`（请求类）也无需 ACK**：请求命令自有对应的 `*_RSP` 应答帧——**RSP 本身就是送达确认**（收到 RSP 即知请求已达），51 无多余回帧；请求超时未收到 RSP 由 8266 发方重发即可。**若再把 REQ 列入需 ACK，一个请求会引出 `ACK(REQ)`+`RSP` 两个回帧，重复确认、流量×2、51 空间浪费（过设计）**。修正：REQ_x 用「RSP 超时重发」兜底，不进 ACK 名单。
- **收方动作**：收到需 ACK 的命令且**处理成功** → 回 `ACK(被确认cmd)`。
- **发方动作**：发需 ACK 命令后开启重试窗（建议 ~300ms，覆盖 9600 下残帧抖动）；窗内未收到对应 `ACK` → 重发，最多 3 次。
- **幂等约束**：重发可能重复送达 → 受 ACK 保护的命令处理必须**幂等**（如 `RING` 触发长鸣须判「已在响，重复不叠加」；`SET_CFG` 重复整帧覆盖无后患）。

### 4.3 ACK 不破坏现有工装

- 旧帧格式、命令码、`uart_8266_sim.py` / `com_cfg.py` / `test_proto.py` 的编解码逻辑**不改变**；仅新增 0x85 分支。
- 工装若收到需 ACK 帧而新固件未接 → 只是超时重发，不挂死（现有超时重发语义已兜底）。

## 需求⑥⑦落点说明

- **⑥ 8266 读传感器**：解决 E5 的「温度校准读数由用户抄屏」痛点 → 8266 发 `REQ_SENSOR`，51 回 `SENSOR_RSP` 含**光敏 raw + 热敏 raw + 已换算温度×10**（决策⑪）。Web 校准页直接读温度显示「当前读数」，用户填实际温度算 offset；光敏 raw 供环境亮度诊断。**8266 不复刻 NTC 公式**（换算权威留 51），51 仅在请求时执行 `adc_read()`（main.c:24）+ ntc 换算，不做周期上报。
- **⑦ ACK**：弥补协议当前「无 ACK，超时 1s 重发≤3」的盲发机制，让 8266 侧命令（SET_CFG/RING/REQ_x）有送达确认。

## 六、风险、隐患与回滚

- **P9 帧长变更（最大）**：54→13 牵动 config.h/协议/镜像/Web/铁律。Phase 1 单独做旧→新兼容测试锁死，期间不并行开发其它阶段。
- **P13 判定只信 DS1302 读值**：8266 判定瞬间必须用「刚读到的 51 时钟」，**不得混用其 NTP 软件时钟**（8266 推 `SET_TIME` 有延迟，两者短期不一致）。
- **P10 贪睡/重响状态不同步**：51 本地自治重响，8266 判定窗口已过不重复下发。**Web「响铃中」状态不实时反映重响**——属已知可接受差异，报告说明。
- **P16 双端升级顺序（关键，防退化回滚）**：**必须 8266 先烧、51 后烧**。若 51 新固件 + 8266 旧固件：8266 仍按旧协议只推 `SET_CFG(54B)` 且 51 已不解析闹钟字段/已改帧长 → **闹钟静默失效，比现状退化**。烧录清单必须标注顺序。
- **P14 串口流量**：高频读每秒 ~10ms（2 帧×~5ms），与 `SET_CFG` 59B 大帧、倒计时推帧错峰（51 `URX_LEN=32` 环缓冲）。评估调度，必要时增大缓冲或错开相位。
- **P15 手动设时间误触发**：用户长按 SET 改 DS1302 时间时，8266 若正处判定窗口可能读到时间跳跃而误响。需判定加「时间单调性/跳跃阈值」校验，或协议标志「设置中」。
- **P17 响铃来源撞码**：见第二节，`ring_alarm` 语义表需统一后定码，防止外部长鸣与残留本地来源冲突。
- **P18 判定模块归属**：并入 `wifi_task.cpp` vs 新建 `sched` 模块——优先级并入现有文件（Ponytail 最小化），除非耦合过重。
- **P19 ACK 流量与 51 空间（需求⑦代价）**：ACK 只在命令性帧启用（§4.2），单次 ACK 1B 载荷 + 帧头，9600 下 ~1.2ms，开销可控；但 51 侧新增 ACK 状态机（~10–15B）+ ADC 上报（~15B）会占重构精简腾出的空间，**须待重构完成（51 有余量）再合入**，否则打回 95B 红线的死胡同。**故 ⑥⑦ 与重构强耦合，不独立前置实施。**
- **P20 ACK 重发与通道竞争**：8266 重试窗内若正逢 51 上行帧（HEARTBEAT 等），需帧间 ≥5ms 对齐；51 `URX_LEN=32` 环缓冲须容纳 ACK + 数据交错，评估必要时错相位。
- **P21 `CD_CTRL` 废弃的兼容**：倒计时按键从「51 定向发 `CD_CTRL`」改「51 广播 `BTN_EVENT` + 8266 裁决」。既有 `uart_8266_sim.py`/`test_proto.py` 若仍按 `CD_CTRL` 驱动倒计时按键，Phase 4.1 需同步改走 `BTN_EVENT`；8266 端保留 `CD_CTRL` 解析兼容（忽略或仍处理），避免旧工装误判。
- **P22 计时器秒基准漂移**：51 原计时器用 DS1302 秒逐秒对齐（main.c:418 捕获 `tm_last`），迁 8266 后用 millis() 1s 台（同倒计时），有累积漂移。**短时工具可接受（决策⑫）；若需长期高精度计时，8266 端可定期读 `REQ_TIME_RD` 对齐秒基准**——默认不做（Ponytail，YAGNI），留作升级路径。
